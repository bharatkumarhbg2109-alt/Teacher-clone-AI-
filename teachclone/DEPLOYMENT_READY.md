## How to Run Locally (Free Mode)

### Prerequisites

- Python 3.11+
- Node.js 18+
- Ollama (for local LLM, free)

### Step 1: Clone and Setup Backend

```bash
cd apps/api

# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Copy environment file
cp ../../.env.example .env

# Edit .env — only these need values for local dev:
#   SECRET_KEY=<auto-generated on first run if DEV_MODE=true>
#   DATABASE_URL=sqlite+aiosqlite:///./teachclone.db   (default, no change needed)
```

### Step 2: Run Backend

```bash
cd apps/api
source .venv/bin/activate

# Start the API server
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

On first run with `DEV_MODE=true`, a `SECRET_KEY` is auto-generated and printed to console.

### Step 3: Setup Frontend

```bash
cd apps/web
npm install
npm run dev
```

Frontend runs at `http://localhost:3000`.

### Step 4: Install Ollama (Free LLM)

```bash
# Install from https://ollama.com
ollama pull llama3.1
```

This gives you a free local LLM for the Teacher DNA pipeline. No API key needed.


## Security Features Implemented

- ✅ **SECRET_KEY guard** — auto-generates in dev, enforces 32+ chars in prod
- ✅ **DEV_MODE guard** — refuses to start if DEV_MODE=true in non-local ENV
- ✅ **CORS** — reads from ALLOWED_ORIGINS env, no wildcard in production
- ✅ **Rate limiting** — auth (IP-based with backoff), upload, voice, public, chat, DNA
- ✅ **Input validation** — strict Pydantic schemas, query param bounds, XSS rejection
- ✅ **Error handling** — global exception handlers, no stack traces leaked to clients
- ✅ **File upload safety** — magic byte verification, MIME allowlist, size limits, S3 presigned POST conditions
- ✅ **Secrets scan** — no hardcoded keys, .gitignore covers .env/.pem/.key
- ✅ **Dependency audit** — Pillow 12.3, nltk 3.10, python-multipart 0.0.31, cryptography 49.0, PyJWT 2.13
- ✅ **Embed JWT** — no hardcoded fallback secret, RuntimeError if SECRET_KEY missing
- ✅ **Webhook verification** — Clerk webhooks verified with svix signature check
- ✅ **Startup secrets check** — requires SECRET_KEY + ANTHROPIC_API_KEY + CLERK_SECRET_KEY in production
- ✅ **Frontend validation** — maxLength on all text inputs, disabled send button on empty/oversized

## Known Remaining Risks

1. **2 postcss vulnerabilities** inside next's own node_modules (requires next@16 breaking upgrade — documented, acceptable)
2. **pip-audit network timeout** in CI — recommend running `pip-audit` in your CI pipeline with proper network access
3. **Pillow 12.x breaking change** — dropped Python 3.8 support (we're on 3.10+, fine) — run a smoke test with PDF/image processing
4. **Magic byte validation** runs at upload_initiate time — S3 presigned POST conditions enforce size and Content-Type at storage layer
